# EveJS 261115.2 compatibility: Asteroid Erosion 0.2.4

Qualified on Windows Native with the actual EveJS 261115.2 server and its
matching retail client. Earlier declared native versions remain in the manifest;
this release's new runtime qualification is specifically for 261115.2.

The updated native presentation hook introduces authored fixed-radius mission
rocks. Erosion now respects that boolean marker in both presentation and radius
publication. Ordinary ore retains its volume-based shrinking. Native ore yield,
waste, cargo, stock persistence and final depletion remain authoritative.

The reviewed login source adds the staff-only native health window. Erosion
preserves that expression, role gate and integer-zero signature. Exact source
guards remain in place, including a separately reviewed GridCheck client-agent
patch. Unknown source is not accepted merely because it has a version label.

Completed qualification covers focused source/client/release contracts, actual
native mining, rendered model/radius agreement, live dust, bubble re-entry,
partial and depleted ore across full same-world server/client cold restarts,
saved visual preferences, combined-mod mining and retail-client reconnect.

Coverage limits are deliberate: the individual persistence fixture used native
authored ore. The combined run measured shrinking and model agreement on natural
belt ore; its short dust burst fell between samples. Individual runtime evidence
supplies the dust check. Fixed-radius mission behavior and multiple-observer
routing have actual-source controls, rather than separate retail scenarios.
The other depletion finishes retain focused client coverage. This is not a new
Docker/Linux runtime qualification or a separate natural-belt save-migration test.

Server configuration and all client payload files are unchanged from 0.2.3.
Launcher updates preserve `config.json`; personal visuals keep the existing
native per-character settings key. No mod-specific save reset or migration is
required. Close clients and stop the game server for the update, then fully
restart the clients to receive the companion at login.
