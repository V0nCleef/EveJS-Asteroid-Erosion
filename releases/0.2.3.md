# Asteroid Erosion 0.2.3

Compatibility update for **EveJS 261108.1 Native**.

- Supports the updated mining and login flows so ore shrinking, dust and the
  client companion attach correctly on this EveJS release.
- Preserves server configuration, personal visual preferences and all four
  depletion styles. Earlier supported EveJS versions remain supported.

**Upgrade:** close EVE clients and stop the Game server, then update Asteroid
Erosion through **Launcher → Mods**. Updates from 0.2.0 onward preserve
`config.json`; personal settings stay in the client profile. Fully reopen clients
after updating so the login companion reloads. Launcher 1.0.69 or newer is required.
For 0.1.6, follow the manual migration instructions in the README.

Real-client qualification on 261108.1 covered shrinking, active dust, native
depletion, re-entry and persistence across a server/client restart. The test mined
333 units, with exactly 333 units delivered to cargo. Josh also reported that his
basic mod testing seemed fine before approving release.

The real-client case used native mission ore and the default dust finish.
Other finishes and two-observer routing retain focused test coverage. See the
[compatibility and verification record](../docs/compatibility-261108.1.md) for scope.

This release publishes the exact qualified 84,419-byte ZIP. Its embedded README
and VERIFICATION describe preparation-time status; this release note and the
linked record contain the later runtime evidence and publication context.
